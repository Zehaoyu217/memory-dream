## T1
- Prefix every feature with the collections domain code `col_`, in snake_case, with the window in the name (memory/prefs/aisha-khan-feature-prefix.md)
- Use the store form `<domain>_<agg>_<window>` with the window last and no `feat_` prefix, e.g. `col_spend_sum_30d`, `col_dpd_max_90d`. This also meets Aisha's rule. The `feat_` aliases expired on 2026-03-09, so the old `feat_<source>_<metric>_<window>_v<n>` pattern is retired (memory/feature-store-migration/dec-fsm-naming-rule.md; memory/howto/feature-naming-convention.md)
- Spell words out: the only abbreviations allowed are `pct` and `cnt` (`amount`, not `amt`) (memory/prefs/tomas-rivera-column-naming.md)
- Add a `<feature>_isnull` companion to any numeric feature with more than 2% nulls, with the median imputed on the training split only (memory/howto/missing-value-indicator.md; memory/howto/imputation-fit-on-train-only.md)
- Delinquency features: DPD day 1 is the day after the due date, and a payment on the due date counts as 0 DPD (memory/corrections/dpd-due-date-offbyone.md). Buckets are 0 / 1–29 / 30–59 / 60–89 / 90+, and "30+" means DPD of 30 or more (memory/howto/dpd-bucket-labelling.md; memory/qa/dpd30-includes-exactly-30.md)
- Roll features are measured per billing cycle as a % of the prior bucket, not per month (memory/prefs/raj-patel-roll-rate-units.md). They cover every transition and are balance-weighted, except the 0-to-30 headline, which stays on account count (memory/corrections/roll-rate-all-buckets.md)
- Spend features exclude reversals (memory/qa/spend-30d-feature-name.md). Join transactions to the prior month-end account snapshot (memory/howto/join-txn-to-accounts.md)
- No feature reads data after the observation date, which is the last day of the statement month (memory/howto/leakage-check-post-period.md; memory/corrections/observation-date-last-day.md)
- Give the model id as `col-<algo>-v<n>` in backticks at first mention, with the eval set after it. A changed feature set means a new version, never a rename (memory/reporting/model-naming-convention.md; memory/prefs/alex-chen-model-id-naming.md)
- Feature-table PSI: top-20 features, on 10 training-quantile bins fixed at registration. A collections model triggers a drift review above 0.25 and is "watch" from 0.10 to 0.25. Anything above 0.10 is investigated (memory/reporting/monthly-review-psi-trigger-v2.md; memory/reporting/psi-bin-convention.md; memory/corrections/psi-two-tier-thresholds.md)
- The collections model's PSI reference is the flat training sample, not same-month-last-year (memory/model-monitoring/dec-mm-seasonal-reference.md)
- Print the case count beside any rate, e.g. "4.1% (n = 318 cases)". Groups under 200 show the count and "n<200" (memory/prefs/raj-patel-counts-beside-rates.md; memory/reporting/min-sample-for-rates.md)
- Quote metrics only for a registered model with a version tag and SHA-256, otherwise mark it "unregistered". Every metric carries its eval set name and n (memory/prefs/aisha-khan-model-registration.md; memory/prefs/sam-lee-metric-decimals.md)
- If the feature table would push the main deck past 12 slides, it goes in the appendix (memory/reporting/deck-length-and-appendix.md)
